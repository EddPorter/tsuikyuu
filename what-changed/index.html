What changed?

A diff shows what changed between two versions of a text. It looks like bookkeeping, but behind it is one of the best-known uses of dynamic programming: finding the most that two texts have in common, and calling everything else a change. This page builds that idea up from two short strings to a full diff, and then to edit distance.

What a diff is

Give a diff two versions. It prints what was removed, what was added and what stayed. Edit either side below. A diff can compare whole lines, as version control usually does, or words, or single letters.

Compare by

Removed pieces are red and struck through (or marked with a minus), added pieces are green (or marked with a plus). One thing is worth noticing. The diff never says why something changed, and it does not know that a line was edited. It sees only that some pieces are in one version and not the other. The rest of this page is about how it decides which pieces count as the same.

Keep as much as possible

Here is the central idea. Whatever the two versions share, in the same order, can be kept. Everything else in the first version is deleted and everything else in the second is added. So the smallest list of changes is found by keeping as much as possible. That is the longest common subsequence: the longest run of pieces that appear in both, in order, though not necessarily next to each other.

There can be more than one longest subsequence of the same length, so different diff programs can give different, equally small answers. That is one reason two tools can disagree about a diff without either being wrong.

The grid

How do we find it without trying every subsequence? A string of 14 letters has 16,384 subsequences (two choices, keep or drop, for each letter), and the number doubles with every letter added. Instead, build a grid with the first string down the side and the second across the top. The cell in row i and column j answers a small question: how long is the longest common subsequence of the first i letters of one string and the first j letters of the other?

Each cell is filled using only cells already filled:

The letters are equal
Take the cell diagonally up and to the left, and add one. We can keep this letter on top of the best answer for everything before it.
They differ
One of the two letters cannot be kept. Take the larger of the cell above (drop the side letter) and the cell to the left (drop the top letter).

The bottom-right cell is the answer for the whole strings. Step through it. Cells with a heavy grey border are where the two letters match.

The grid gives the length of the longest common subsequence. To find which letters it is, and so the diff itself, walk back from the bottom-right corner to the top-left, asking at each cell how its number was made:

The two letters are equal
That letter was kept. Move diagonally up and left, to the cell the number came from.
They differ, and the cell to the left is at least as big as the cell above
The number came from the left, so the top string’s letter for this column was added. Move left.
They differ, and the cell above is bigger
The number came from above, so the side string’s letter for this row was deleted. Move up.
At an edge
If one string has run out, whatever is left of the other is all added or all deleted.

You reach the top-left corner after as many steps as there are changes and kept letters. The steps come out last to first, so reverse them to read the diff in order. When the left and above cells are equal, either choice is valid, and this page goes left. Going up instead would give a different but equally short diff. Fill the grid, then walk back one step at a time.

keep (letters equal)add (came from the left)delete (came from above)

The grid has one cell per pair of positions, so its size is the length of one string times the length of the other. That is a few hundred steps for these strings, rather than thousands of subsequences, and it grows by multiplication where trying every subsequence grows by doubling. This is the whole idea of dynamic programming: answer small questions first, write the answers down, and build the big answer from them.

Edit distance: allow a swap

A diff can only add and delete. If one letter becomes another, a diff sees a deletion plus an addition. Often what you want to know is how many single-letter edits turn one word into another, where an edit may be an insertion, a deletion or a substitution. That number is the edit distance, often called Levenshtein distance. It is what spelling correctors and “did you mean” suggestions use to rank candidate words.

The grid is almost the same, with two changes. It holds the smallest number of edits where the other held the longest common subsequence, and a substitution is a third way into each cell. Each cell is the smallest of three: the cell above plus one (delete a letter), the cell to the left plus one (insert a letter), and the diagonal cell plus zero if the letters are equal, or plus one if not (keep the letter, or swap it).

Walking back works the same way as before, from the bottom-right corner. At each cell, find which of the three gave its number. If it was the diagonal, the move is either same (the letters are equal, no cost) or a swap (the letters differ, cost one). If it was the left cell, a letter was inserted. If it was the cell above, one was deleted. A swap and a same move both go diagonally, and the only way to tell them apart is whether the two letters are equal, so the grid below labels every cell on the path. The walk checks the diagonal first, then left, then above, so ties go to the diagonal.

same (letters equal, no cost)swap (letters differ, cost 1)insert (from the left, cost 1)delete (from above, cost 1)

Real files are big

A source file can have thousands of lines. A grid of 1,500 by 1,500 has over two million cells, and it keeps all of them in memory so it can walk back. Real diff tools use shortcuts. The simplest is to trim first: lines that are identical at the very start or very end of both versions cannot be changes, so skip them and fill the grid only for the middle.

Try it. This makes two made-up files of 1,500 lines and changes some lines in the second. Then it finds the longest common subsequence twice, once on the whole files and once after trimming, and reports the work and the time. The result must agree.

Where to go next

Names to search for. They are pointers, not explanations.

Myers’ diff algorithm
A faster method that does work in proportion to the number of changes, so two nearly identical files are cheap. Git’s documentation lists it as the default algorithm, alongside minimal, patience and histogram options.
Hirschberg’s algorithm
Finds the same answer as the grid while keeping only a couple of rows in memory, by splitting the problem in half repeatedly.
Patience and histogram diff
Variants that anchor on lines occurring exactly once, which often give diffs that read better for source code, even when they are not the shortest.
Needleman–Wunsch, Smith–Waterman
The same grid applied to DNA and protein sequences, with scores for matches and gaps. A close relative of the scoring grid on Best match first.
Three-way merge
Diffing two edited copies against a common ancestor, which is how tools merge branches.
Related pages
Another use of a grid, ranking fuzzy matches, is Best match first. Spotting near-copies without aligning them is Nearly the same.

In short

  • A diff keeps what two versions share, in order, and calls the rest changes.
  • Keeping as much as possible is the longest common subsequence problem.
  • Trying every subsequence doubles with each letter. A grid of small answers needs only one cell per pair of positions.
  • Each cell depends only on three neighbours, so it is filled in order and walked back to recover the answer.
  • Edit distance is the same grid with a substitution allowed and the smallest count in place of the longest run.
  • Real tools trim, and use cleverer methods, to cope with large files.

The whole paragraph

Every word processor has to break a paragraph into lines. The obvious method fills each line as full as it can and moves on. A better one looks at the whole paragraph and chooses all the breaks together, accepting a slightly short line here so that nothing is badly stretched there. This page shows why the obvious method falls short, and how dynamic programming picks the best breaks. It is the idea behind the line breaking in TeX, due to Knuth and Plass.

The obvious way

Put words on a line while the next one still fits. When it does not, start a new line. This is greedy: each line takes everything it can, and a decision once made is never revisited. It is simple, quick, and it is what most text boxes do.

The trouble is that taking everything on one line can leave the next line with awkward material. A long word may not fit, and then the next line starts with it while the previous line is left short. You can have a nice line followed by a dreadful one, and no way back.

Scoring a line

To compare two ways of setting a paragraph we need a number for each. This page uses a simple one. Each line has a width, measured in characters, and the words plus single spaces take up some of it. The unused remainder is the line’s slack, which is also its looseness score. In a justified paragraph that slack has to be spread across the gaps between words, so a line with a lot of slack looks loose and gappy. The cost of a line is its slack raised to a power. With plain slack, the total depends almost only on how many lines the paragraph takes, so one huge gap costs the same as the same space spread over several lines, and the best setting just tries to save lines. Squaring makes one very loose line cost much more than several slightly loose ones, which is usually what you want. Higher powers, such as cubed, mostly choose the same breaks as squared, so this page offers just these two. The last line of a paragraph is allowed to be short, so it costs nothing.

The best setting is the one with the smallest total cost over all the lines. Greedy does not look at the total at all.

Choosing all the breaks together

Greedy breaking goes wrong because it decides each line without asking what it leaves for the next. To do better we want the cheapest total. There are far too many ways to break a paragraph to try them all: each gap between words is a break or not, so a 100-word paragraph has an astronomical number of settings. But there is a shortcut, and it rests on one fact.

The cheapest way to set the first j words is the cheapest way to set some shorter run of words, plus one more line.

Here is why. Take the cheapest setting of the first j words and look at its last line. Say it holds words i+1 to j. Everything before that line is a setting of the first i words, and it must be the cheapest one possible. If it were not, swapping in a cheaper one would make the whole setting cheaper, which contradicts it being the cheapest.

So we keep a list called best, where best[j] is the lowest cost of setting the first j words as complete lines. We fill it in from the start:

  1. best[0] = 0. Setting no words costs nothing.
  2. For each j in turn, from 1 up to the number of words, list every last line that could end at word j. That is words i+1 to j for each i that still fits on one line.
  3. For each of those, work out total = best[i] + the cost of that last line. best[i] is already known, because i is smaller than j.
  4. The smallest total is best[j]. Also remember which i gave it.

When best[n] is done for all n words, that is the cheapest cost for the whole paragraph. To read off the lines, look at which i was remembered for n: the last line starts at word i+1. Then look at what was remembered for that i to find the line before it, and so on back to the start.

What the real thing adds

This page uses the idea in a stripped-down form. The real algorithm is described in the Knuth–Plass paper, “Breaking Paragraphs into Lines”, in Software: Practice and Experience, 1981.

Stretchy gaps
Each space has a natural width and amounts it may stretch or shrink. A line’s cost depends on how far its gaps must go from natural, not on a count of characters.
Penalties and hyphens
Some places are allowed breaks at a cost: after a hyphen, or inside a word if hyphenation is allowed. Others are discouraged, such as leaving a single word alone on the last line.
Looking only at sensible breaks
It keeps only the break points that can still lead to an acceptable line, so the work stays manageable for a whole page of text.
Paragraph, not page
It breaks one paragraph at a time. Breaking paragraphs across pages is a separate problem with its own rules.

In short

  • Greedy line breaking fills each line and never looks back, so one choice can force a bad line later.
  • Give each line a cost from its slack, and the best setting is the one with the smallest total.
  • The cheapest way to set the first j words depends only on cheaper answers for fewer words, so a table of small answers solves it.
  • Remembering which choice won at each step lets you walk back and read off the lines.
  • The real algorithm adds stretchable gaps, hyphenation and penalties on top of the same plan.

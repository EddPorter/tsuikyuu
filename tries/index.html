Shared beginnings

Many words start the same way. A trie is a tree that stores each shared beginning once. This page builds one a letter at a time, uses it to find words by their start, counts what it saves, squashes it into the structure behind suffix trees, and then shares the endings too.

It follows on from Just enough letters, which looks for the fewest letters that pick out one word from a list. You do not need to have read that first, and it is linked where it matters.

Finding words by their start

Suppose you have a list of words and want every word that starts with the letters someone has typed. The obvious way is to look at every word in the list and compare its first letters with the prefix. Type a prefix below and watch how many letters get examined.

Every word is examined every time, even the ones that obviously cannot match. With six words that hardly matters. With six hundred thousand it matters a great deal. A trie is a way of not looking at most of them.

To add ted afterwards, the t and e branches already exist, so follow them and only make the d. Words that start the same way share the start. The code that does this is short. Each node holds its children (a map from a letter to the next node), a count of how many words pass through it, and a flag for whether a word ends there.

Looking things up

To find every word that starts with a prefix, walk down the tree one letter at a time. If a letter has no branch, nothing starts that way. If you arrive at a node, every word below it starts with your prefix, and collecting them is the autocomplete. The number of steps depends on the length of the prefix, and not at all on how many words there are.

Collecting the words below the node takes time proportional to how many there are, so the trie's advantage is in not wading through the words that cannot match.

Counting at the nodes

Each node also keeps a count of how many words pass through it. That count answers questions for free. The number beside a node is how many words start with the letters on the path to it. A node whose count is 1 has only one word below it, so the path to it is enough to pick that word out. The first such node on a word's path gives its shortest unique prefix, which is exactly the Starts with rule from Just enough letters.

What it saves, and what it costs

A flat list stores every letter of every word. A trie stores one letter for each node, and shared beginnings are stored once. When many words share their starts the trie holds fewer letters. When none do, it holds exactly as many, plus the cost of the links between nodes. Real memory depends on how those links are stored, so fewer letters is not always fewer bytes.

The same comparison for the index used on Just enough letters is in the memory part of Scan or index?. That index holds every piece of every word, so a trie saves far more there than it does here.

Squashing it

Many nodes have only one child. A path of such nodes can be squashed into a single edge labelled with all its letters. The result is called a compressed trie, or radix tree. It has fewer nodes and holds the same words, and the saving grows as words get longer and branch less.

Now a bigger idea. Instead of the words themselves, put every ending of every word into the trie: banana gives banana, anana, nana and so on. A trie of all the endings contains every piece of every word as a path from the root, and squashing it gives a suffix tree. That is the structure that the sorting method in Just enough letters was standing in for. Try both views, and try a single longer word such as banana, where squashing saves the most.

Sharing the endings too

A trie shares beginnings, but nothing else. Look at talked and walked in the Verbs list. After their different first letters, both continue alked, and the two branches are identical copies. Any two parts of the tree that spell out exactly the same endings can be merged into one. Then the structure is no longer a tree, because two different paths can arrive at the same node. It is a graph, with no loops, and the leaves, the ends of words, are shared too: every word that finishes at the very end of its path can finish at the same single node.

Tick the box and watch the pieces collapse. Counts are not shown, because a merged node stands for several words at once.

This structure is usually called a DAWG, a directed acyclic word graph, or a minimal acyclic finite-state automaton. It is used to store large word lists compactly: Appel and Jacobson’s 1988 article on a very fast Scrabble program used one for its word list. It gives up some things to get there. A node no longer belongs to one word, so it cannot carry data for a single word, such as a count. And adding a new word to a merged graph is harder than adding one to a trie, because a merged piece that other words share may have to be split apart first. For that reason it is usually built once from a finished list.

The parts you can swap

As in the other explainers, the walk down the tree stays the same while two choices change what the tree can do.

PartOptionsWhat changes
What a node storesAn end flag, a count, a list of wordsWhether it can answer “is this a word”, “how many start this way” (as above), or “which ones” without walking further.
How children are heldA map, a fixed array, a sorted listSpeed of each step against memory per node. A fixed array of 26 slots is fast but wasteful when most are empty.
Whether to squashPlain, or compressedFar fewer nodes, at the price of splitting an edge when a new word diverges halfway along it.
Whether to merge endingsA tree, or a merged graphFewer nodes again, at the price of losing per-word data and easy insertion.
What goes inWhole words, or every endingA dictionary of words, or an index of every piece of every word (a suffix tree once squashed).

In short

  • A trie stores each shared beginning once, with a path of letters for each word.
  • Looking up a prefix is a walk down the tree, so its cost depends on the length of the prefix and not the size of the list.
  • A count at each node answers “how many words start this way”, and the first node with a count of 1 gives a word's shortest unique prefix.
  • Squashing single paths gives a compressed trie, and a squashed trie of all the endings is a suffix tree.

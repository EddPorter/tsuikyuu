Where am I, and where is everything?

Put a robot in an unknown place. To know where it is, it needs a map. To build a map, it needs to know where it is. SLAM, simultaneous localisation and mapping, solves both at once. This page builds on How much to believe: the same idea of weighing a prediction against a reading, with a robot and its landmarks estimated together.

The chicken and the egg

Suppose a robot drives round a room. It has no GPS, only two kinds of information.

Odometry
Its own sense of how far it has moved and turned, from counting wheel rotations. Always a little wrong. Every wrong step is added to the next, so the error grows without limit. Working out a position by adding up movements is called dead reckoning.
Landmark sightings
A sensor that reports, for each landmark in view, how far away it is and in which direction relative to the robot's heading. Also a little wrong, but the error does not grow with time, because each sighting is a fresh measurement.

If the landmarks were at known positions, each sighting would pin the robot down: that is localisation. If the robot knew exactly where it was, each sighting would show where a landmark is: that is mapping. In SLAM neither is known, so the robot has to improve both from the same sightings.

One belief for everything

The key step is to stop treating the robot and the landmarks as separate things. The filter keeps one long list of numbers: the robot's position and heading, followed by the position of every landmark found so far. It also keeps one uncertainty table for the whole list, as on the previous page, but now the table says how every number is related to every other.

Those relations matter. When the robot first sights a landmark, the landmark’s position is worked out from the robot’s position, so any error in one is shared by the other. The two beliefs are linked. Later, when the robot finds out it was wrong about where it was, the links let the filter fix the landmarks it placed earlier as well. Without the links, a correction to the robot could not reach them. You can switch the links off below and see what happens.

Each step has the same two parts as the Kalman filter:

Predict
The robot moves. Its position changes according to the odometry, and its uncertainty grows, since odometry is noisy. The landmarks have not moved, so their numbers stay put. The links to the robot stretch the uncertainty of anything linked to it, too.
Update
The robot sights a landmark. If it is new, add it to the list and link it to the robot. If it has been seen before, compare where the robot would expect to see it with where it did see it, and correct everything, weighted by the uncertainties.

Things to try:

  • With sightings on, watch the robot’s uncertainty ellipse when it first returns to a landmark it saw long before. It usually shrinks sharply, and the status line says so. This is loop closure, the moment SLAM is built around.
  • At the same moment, look at the landmark ellipses and the mean landmark error. Landmarks seen early on get corrected too. That is the work of the links.
  • Tick “Forget the links”. The ellipses shrink to a fraction of their size, but the errors do not, so the filter now claims far more certainty than it has earned. It is usually less accurate as well, though not on every noise pattern. Try New noise a few times. The filter has stopped admitting how much its beliefs depend on each other.
  • Shorten the sensor range so that the robot loses sight of landmarks for long stretches.
The code (it is what this page runs)

What the filter is doing

The state
Robot position (two numbers) and heading, then two numbers for each landmark found so far. With L landmarks that is 3 + 2L numbers.
The uncertainty table
A square table with that many rows and columns. Its diagonal holds each number’s own variance, and the other entries hold how pairs of numbers vary together.
Predict
Move the robot by the odometry. Work out how the new pose depends on the old pose and on the odometry noise, and use that to grow the table, as in the Kalman filter, but in several dimensions.
A new landmark
Place it at the sensed distance and direction from the robot. Its uncertainty comes from the robot’s uncertainty plus the sensor’s. Add a row and column that link it to everything the robot is linked to.
A known landmark
Compute where the sensor should report it, from the current belief. The gap between that and the real reading is the innovation. The gain, as before, depends on how uncertain the belief is compared with the sensor, and now it also spreads the correction over every number the sighting is linked to.

The movement and the sensor both involve angles and distances, which are not straight-line relationships. The filter handles this by treating them as straight lines over a small region, using their slopes at the current estimate. That version is called the extended Kalman filter, and it is what this page uses.

What this page leaves out

  • It knows which landmark is which. Here every sighting arrives labelled. A real robot has to decide whether a blob it sees is a landmark it has seen before or a new one, and a wrong decision can ruin the map. This is called data association.
  • It starts at a known place. The robot’s starting position defines the map’s origin. The map is relative to it.
  • It does not scale. The uncertainty table has a row and column for every number, so it grows with the square of the number of landmarks, and each update touches all of it. Large maps need other methods.
  • It can be confidently wrong. The straight-line approximation of the angles is only good while the heading error is small. With little to see, such as a sensor range of 16 on the first noise pattern, the filter can end up several units out while its ellipse says it is within three or four. Real systems check for this, and use other methods when it matters.
  • The noise levels are assumed. As on the previous page, the filter is told the true noise levels. Wrong ones give overconfident or sluggish behaviour.

Where to go next

Names to search for. They are pointers, not explanations.

Particle-filter SLAM
Hold many guesses of the robot’s path at once, each with its own map, instead of one bell curve. The idea behind a family of methods usually called FastSLAM.
Graph-based SLAM
Keep a list of poses and the constraints between them, such as “these two poses saw the same landmark”, and find the layout that disturbs the constraints least. It is widely used for large maps.
Loop-closure detection
Recognising a place already visited, from its appearance, without relying on the robot’s estimate of where it is.
Scan matching
Using the overlap between successive laser or depth scans to estimate movement, in place of wheel counting.

In short

  • Odometry alone drifts without limit, and a map needs to know where the robot is.
  • SLAM keeps one belief about the robot and every landmark, with one table of how they all vary together.
  • Each step predicts with the odometry, which grows the uncertainty, and updates with sightings, which shrinks it.
  • The links between robot and landmarks let a late correction fix the earlier map. Dropping them makes the filter overconfident.
  • Re-sighting a landmark seen long before, loop closure, is where the uncertainty falls most.

Read it backwards

To find a word in a long text, the obvious method checks every position from the left. A cleverer method lines the word up and compares it starting from its last letter. That odd choice lets it jump ahead and skip most of the text without ever looking at it. This page builds the idea up with a version called Boyer–Moore–Horspool, and measures how much it skips.

The obvious way

Write the text on one line and the word you want, the pattern, underneath. Start with the pattern at the left edge. Compare its letters with the text above them, one by one from the left. If they all match, you have found it. If one differs, slide the pattern one place to the right and try again.

That is correct and easy to write, but every letter of the text gets looked at, and often several times, because after a mismatch the next attempt starts again from the pattern’s first letter. Most mismatches come on the first or second letter, so the cost is typically between one and two comparisons per letter of text, depending on the kind of text. The question is whether we can do better than looking at every letter. It sounds impossible, but it is not.

Start from the other end

Suppose the pattern is stone and it is currently lined up under the text letters x y z w q. Compare the last letters first: e against q. They differ. Now ask a different question: could any alignment put the pattern’s last place under that q and still match? Only if the pattern contains a q. It does not. So no alignment that covers that q can possibly match, and we can slide the pattern completely past it, by the full length of the pattern, five places, without looking at the four letters in between.

If the text letter under the pattern’s last place is in the pattern, slide just far enough to line up the nearest copy of that letter in the pattern with it. That gives a small table, one number per letter of the pattern: how far from the end of the pattern its last occurrence is. Letters not in the pattern get the full length. This version, which only ever looks at the text letter under the pattern’s last place to decide the slide, is called Boyer–Moore–Horspool. The original Boyer–Moore adds a second rule, noted near the end.

Notice what this does: a longer pattern means bigger jumps. The usual intuition is that a longer word is harder to find. Here it is easier.

Each method is a generator that reports every comparison and every slide as it happens. The page collects those reports, which is how it draws the steps and counts the work. The search itself is just those few lines.

How much does it skip?

One short example proves little. Here both methods search a made-up text of 100,000 characters. For each pattern length it takes three patterns copied from different places in the text, so every search has at least one match, and averages the comparisons per letter of text. Anything under 1 means the method looked at fewer letters than the text contains. The kind of text matters, so try each.

Text

The two kinds of column answer different questions. “Comparisons per text letter” is the total number of comparisons divided by the length of the text, so a letter compared from three different alignments counts three times. “Share of text letters compared at least once” counts each letter once. When slides are long, a letter is rarely compared twice and the two track each other. When slides are short, as with only 0 and 1, the pattern keeps overlapping where it has just been, letters are compared again and again, and the comparisons per letter can sit well above the share of letters touched.

These numbers count comparisons, not time. A real search library also cares about the processor’s memory behaviour and may use special instructions to scan quickly, so fewer comparisons does not always mean a faster program. Treat this as showing the idea, not as a benchmark.

When it does not help

Very short patterns
A one-letter pattern can never jump more than one place. The method needs room to skip.
Tiny alphabets
In a text of only 0 and 1, nearly every letter is in the pattern, so the jumps are short, and the method can end up looking at most of the text. Compare the binary results above with the English ones.
Repetitive text
With text like aaaa… and a pattern like baaa, the simple version can slide only a place at a time and has to compare most of the pattern each time. In the worst case it is no better than the obvious way. The full Boyer–Moore’s extra rule exists to help there.

Where to go next

Names to search for. They are pointers, not explanations.

Full Boyer–Moore
Adds a “good suffix” rule. If the last few letters matched before a mismatch, slide to the next place in the pattern where that ending also occurs. The slide is the larger of what the two rules give. With a further refinement due to Galil, the worst case is time in proportion to the length of the text.
Knuth–Morris–Pratt
Reads the text strictly left to right and never steps back, by precomputing what a partial match tells you. Its guarantee holds on every input.
Rabin–Karp
Compares a hash of each window of text with a hash of the pattern, updated cheaply as the window slides. It extends well to searching for many patterns at once. The idea of hashing small windows also appears in Nearly the same.
Aho–Corasick
Searches for a whole dictionary of patterns in one pass, using a trie with extra links. See Shared beginnings for the trie part.
Indexes
If you will search the same text many times, build an index once (a suffix array, say) instead of scanning each time, as on Just enough letters.
GNU grep
Its original author, Mike Haertel, described its speed as coming from a Boyer–Moore search that looks first for the last byte of the pattern and skips ahead using a table, in a 2010 mailing-list post called “why GNU grep is fast”.

In short

  • The obvious search compares from the pattern’s first letter and slides one place on a mismatch, so it looks at every letter of the text.
  • Comparing from the last letter lets one mismatch rule out many alignments at once.
  • A table with one number per letter says how far to slide. Letters absent from the pattern slide the whole length.
  • Longer patterns slide further, so the method usually looks at only a fraction of the text.
  • It helps least with short patterns, tiny alphabets and repetitive text.
